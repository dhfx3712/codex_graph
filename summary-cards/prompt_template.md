# 摘要卡 → 执行 Prompt 模板（prompt_template.md）

把"卡片 + 模糊需求"转成精确 unified diff 修改 prompt。每次只填三处占位即可。

```
你是一个只做精确代码修改的助手。基于下列信息生成最小改动方案。

【摘要卡】
<粘贴相关的一张或几张卡（前端/后端/数据/外部服务/配置/部署…）>

【模糊需求】
<自然语言描述想达到的效果，可含糊>

【输出格式】
只输出 unified diff，不解释、不整文件、不加 markdown 围栏。
约束：
- 依据卡片"函数地图 / 常见修改点"定位到具体文件、函数、相近逻辑；
- 标准 git unified diff：`--- a/<path>` 与 `+++ b/<path>` 开头，含 `@@` 上下文；
- 仅改与需求相关的行，保持 id / 函数名 / 接口契约兼容；
- 不引入新依赖、不改无关代码、不重构；
- 若需求涉及多文件，分文件输出多段 diff；
- 若命中项目特有坑（如 ENV_FILE 命名 .ollmam_env 与 README 不符、chunks.csv 的 embedding 列恒空、FAISS 维度硬编码 384、模型须本地缓存且设离线变量、query.search 每次重载模型），在 diff 旁用注释点出。

（agentic 执行器提示：你仍应读真实文件对齐行号；卡片用于精准定位与锁输出，非替代读文件。）
```

## 配套用法（本仓库）

- 迭代前先读 `summary-cards/INDEX.md`（几十字）→ 判断涉及哪张卡 → 再 Read 那一张。
- 例：想"新增单词时检测是否已存在"这类需求，本仓库对应"改切片粒度/关系类型/查询逻辑"→ 读 后端卡 + 数据卡 + 外部服务卡。
- 改完代码 → 按 INDEX 映射增量更新对应卡片区块（绝不全量重写），见各卡"常见修改点 / 约束与坑"。
